AICC WEBSITE - COMPLETE INTERVIEW EXPLANATION
Date Prepared: 2026-04-26

============================================================
1) PROJECT IN ONE LINE
============================================================
This is a full-stack-style event management web application for an AI Coding Club, built primarily as a React SPA with Supabase for authentication and database operations, plus role-based admin and user dashboards.


============================================================
2) PRIMARY BUSINESS GOAL
============================================================
The app solves club operations in one place:
- Publicly showcase club information, team, and events.
- Let students sign up/login and register for events.
- Let admins create/manage events and seats.
- Let admins view analytics and export registration reports.
- Let users view tickets and QR codes for registered events.


============================================================
3) HIGH-LEVEL ARCHITECTURE
============================================================
Client:
- React 19 SPA with React Router.
- Tailwind CSS for styling.
- Framer Motion and GSAP for animation.
- Recharts and XLSX for admin analytics/export.

Backend services:
- Supabase Auth for login/signup/OAuth/password reset.
- Supabase Postgres tables for users, events, and registrations.
- Supabase RPC functions for business logic such as registration and seat allocation.

Deployment:
- Vite build pipeline.
- Vercel rewrite rule sends all routes to index.html for SPA routing support.


============================================================
4) APPLICATION FLOW (END-TO-END)
============================================================
A) App startup
- main.jsx renders App inside React StrictMode.
- App fetches current auth session via supabase.auth.getUser().
- If logged in, App fetches user profile from profiles table.
- App subscribes to auth state changes using onAuthStateChange.

B) Routing and access control
- Public routes: Home, About, Events, Team, Auth, Reset Password.
- Protected route wrapper checks if a user is logged in.
- Admin route wrapper checks profile.role equals admin.
- Unauthorized users are redirected with Navigate.

C) Authentication
- Email/password login via signInWithPassword.
- Signup via signUp and then profile row insertion.
- Google OAuth via signInWithOAuth provider google.
- Password reset request via resetPasswordForEmail.
- Password update in reset page via auth.updateUser.
- Logout via auth.signOut.

D) Event registration flow
- EventsPage loads future events from events table.
- Logged-in user registration IDs are loaded from registrations table.
- On Register click, app checks auth state and opens registration modal.
- Registration submission calls RPC register_for_event with structured payload.
- UI updates local registered IDs to prevent duplicate registration actions.

E) Admin event management flow
- AdminEventsPage loads all events and registrations.
- Admin can add event details (name, date, description, location, poster, seats).
- Admin can toggle registration_open flag.
- Admin can add seats; app updates available_seats and calls RPC allocate_available_seats.
- Admin can delete event and related registrations.

F) User dashboard flow
- UserDashboard gets current user profile and registrations.
- Registrations are joined with events details.
- Waitlisted users are shown when ticket_id is null.
- If ticket exists and event is upcoming, user can preview ticket modal and QR code.
- If event is over, user can delete ticket/registration.
- Dashboard auto-refreshes every 3 seconds using setInterval.

G) Admin analytics flow
- AdminDashboard fetches registrations and related events.
- Data is aggregated in-memory by branch/year/department/gender.
- Charts are rendered with Recharts PieChart.
- Export features:
  1. Excel export via XLSX.writeFile.
  2. Chart PNG export by serializing SVG to canvas and downloading image.

6) FRONTEND ENGINEERING CONCEPTS USED
============================================================
Core React concepts
- Functional components throughout project.
- useState for local view state.
- useEffect for side effects and data fetching.
- useMemo for computed/derived values in analytics.
- useRef for DOM refs (chart export) and animation internals.

Routing concepts
- BrowserRouter, Routes, Route.
- Navigate-based redirection.
- Route guards implemented as wrapper components.

State strategy
- No global state library.
- State is colocated in feature pages/components.
- Auth/profile state held at App level and passed into navigation/routes.

Async data access
- Supabase query builder style:
  from(...).select(...).eq(...).single().
- RPC call style for server-side business logic.
- Optimistic/minimal UI updates where practical.

Derived analytics
- Aggregations performed in JavaScript using object maps.
- Converted to chart datasets with reusable helper makePieData.

10) SECURITY MODEL AND PRACTICES
============================================================
Implemented practices
- Authentication handled by Supabase Auth.
- Role-gated admin routes on client side.
- Password reset is token/session-backed via Supabase flow.

Important interview point
- Client-side route guards are UX controls, not final security.
- Real enforcement must be in database policies (RLS), RPC checks, and backend logic.

Potential security hardening opportunities
- Ensure strict Row Level Security on profiles/events/registrations.
- Validate role-based access in RPC and DB policies.
- Add rate limiting and bot controls on auth/registration endpoints.
- Avoid duplicate direct Supabase client creation across files for maintainability.

11) PERFORMANCE CHARACTERISTICS
============================================================
Positive patterns
- useMemo in analytics avoids expensive recomputation.
- Lazy visual interactions are mostly event-driven.
- Data fetches are scoped by page responsibility.

Potential bottlenecks
- UserDashboard polls every 3s (could be replaced with Supabase realtime channel).
- Multiple heavy animation layers can impact low-end devices.
- Some components import assets dynamically and could benefit from explicit optimization.

15) INTERVIEW Q AND A PREP
============================================================
Q1: Why Supabase instead of building a custom backend first?
A: It accelerated delivery by combining auth, Postgres, and RPC in one platform while still allowing strong data-level logic.

Q2: How did you separate user and admin permissions?
A: I used profile.role-based route guards in UI and would enforce final authorization at DB policy and RPC level.

Q3: Why use RPC for registration?
A: Registration and seat allocation are business-critical and better centralized in database functions to ensure consistency and avoid race conditions.

Q4: How did you handle analytics?
A: Registration data is fetched once, transformed into grouped distributions using useMemo, and visualized with Recharts.

Q5: What would you improve first for production readiness?
A: Add strict RLS and RPC authorization checks, replace dashboard polling with realtime channels, and remove unused dependencies/components.

Q6: What React concepts are demonstrated strongly in this project?
A: Hook-based architecture, route composition, state lifting to App for auth/profile, memoized computations, and reusable component patterns.
